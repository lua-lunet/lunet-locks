\section{Experimental results}\label{sec:results20260919}

All numbers in this section are exact counts or exact anchored spans from
three captured runs of the \code{lunet-locks} demonstration
(Section~\ref{sec:demo}), each with its run marker commit in the
demonstration repository anchoring the claim: the steady-state polite run
\code{local-softball7-2026-09-18} (marker \code{81d08ca}; the serving proof
is tagged \code{polite-run-1}, whose message names that marker), the
maintenance ladder \code{local-polite2-2026-09-19} (marker \code{d97b30c}),
and the crash/partition run \code{local-softball8-2026-09-19} (marker
\code{db42519}). Every elapsed time is a $T+\Delta$ difference on the
single acting host's clock (all three runs execute on one host; the cluster
is loopback), never a raw epoch; every distribution carries its sample size
$n$ and its maximum; every headline figure is an exact count, not an
estimate. The datasets, extraction JSONs, and charts live in the run
directories \code{.tmp/telemetry/local-softball7-2026-09-18/},
\code{.tmp/telemetry/local-polite2-2026-09-19/}, and
\code{.tmp/telemetry/local-softball8-2026-09-19/}; each carries a

\subsection{Setup}\label{sec:exp-setup}

Each run is a three-voter cluster of the demonstration on one macOS host:
genesis voters \code{n1}/\code{n2}/\code{n3} (ids 1/2/3) over raw UDP on
loopback (ports 44801--44803 in the steady run, 45201--45203 plus the spare
joiner row \code{n4} at 45204 in the maintenance ladder, 46201--46203 in the
crash/partition run), with TCP client ports alongside. The workload is the
lease API of Section~\ref{sec:demo}: \code{set} grants or renews a 500~ms
lease, \code{get} reads it, \code{release} removes it; every committed
operation is one full consensus round trip (client TCP $\to$ leader $\to$
UDP Prepare/PrepareOk quorum $\to$ Commit fan-out $\to$ apply $\to$ reply).
Three polite \code{lease-load} contenders (client id-bases 810000/820000/830000)
chase one lock, id 14531090, renewing at the half-window point and probing
at a 1{,}000~ms floor; the steady-state run adds a per-operation stream
client (lock 9201) cycling acquire $\to$ 3$\times$extend $\to$ release $\to$
\code{get}, one latency sample per operation. The crash/partition run adds
an aggressive hammer window (2 contenders + 2 getters on the same lock).

The detector configuration is the calm set on every run: heartbeats every
5~ms, \code{--election-ms 3000 --recovery-ms 3000}, the randomized leader
timeout drawn uniformly from 3{,}000--5{,}000~ms (the boot line names
\code{detector=sloppy-timeout}; the Raft timing law, generous lower bound,
random upper). The experimental phi accumulator is compiled out of the
normal build; every leader-loss event in these runs is detected by the
randomized timeout unless the leader is told to abdicate. The telemetry is
the flight recorder: a trailing 200~MiB tape window per node, stringified
state and tag names, every peer-input drop carrying a named diagnostic.
The three runs retain 791,409 wire records (steady-state run, per-datagram
deduplicated: 376,245 emitted + 339,517 received + 75,647 client request
frames), 1,005 status lines, and 8 clean restarts; the crash/partition run
records 783,988 flight records (n1 327,084 / n2 192,502 / n3 264,402).
Every stop record stands on a flushed marker at the same identity: the
shutdown-consistency check reads \code{CONSISTENT} on both the raw
directory and the archive in all three runs (the reports' appendices
reproduce both checks verbatim, 9 nodes checked each time).

The fault-injection discipline differs by run and is stated per scenario:
the steady-state run injects nothing (8 clean TERM stops, zero SIGKILLs,
zero partitions, zero rebirths); the maintenance ladder uses clean TERMs,
the operator verb \code{abdicate} (3 cycles), SIGKILL crashes, whole-cluster
stops, and the controlled decrement/leave/join/increment swap; the
crash/partition run uses SIGKILL (6 family kills + the compound's leader),
SIGSTOP/SIGCONT process suspension as the partition shape (no sends, no
receives, state intact; indistinguishable from a link cut at every other
node's vantage, and the heal is a true partition heal --- the resumed node
replays the socket backlog, no reboot, no identity bump), 126 abdication
drives, and clean TERMs at every boundary.

\subsection{Steady state}\label{sec:exp-steady}

over a 692.2~s client window: 3,803 lease-load operations (1,904 + 1,236 +
663 per client) and 1,192 individually-logged stream-client operations
(200 acquire, 596 extend, 198 release, 198 get). Thirty-five client-visible

The design claim this run measures is the uVRR efficiency shape: the wire
is one stream. The leader re-asserts the commit frontier every heartbeat
(one Prepare fan-out of 2 datagrams + one Commit fan-out of 2), each
follower answers with one PrepareOk, so the heartbeat round costs 6
datagrams; the measured round is 16,301 rounds over the 150.0~s S4 window,
a 9.20~ms mean period, that is 652 datagrams/s cluster-wide (651.6 in S1,
652.0 in S4 under leader n2; 641.0 in S3 under leader n1). Client
operations ride inside that already-running stream: in S4 only 7.3\% of
rounds carried at least one operation (1,187 operations over 16,301
rounds), so the per-operation marginal consensus cost is 0 extra datagrams
when an operation batches into an existing round, bounded above by 6
datagrams if it demanded a dedicated round. Client polls do not touch the
consensus plane at all: in S4 the leader received 17,686 client request
frames (117.9/s) and answered 16,302 TCP replies (108.7/s) while the
consensus plane stayed at 652 datagrams/s. The plane's rate is constant
across every pure steady window while the committed rate varies
(Fig.~\ref{fig:plane-rate}); fast failure detection and nearly-free
operations are the same 5~ms mechanism, not competing costs.

\subsection{The failover lower bound}\label{sec:exp-lower-bound}

The maintenance ladder (2026-09-19) measures the claim this paper makes
about progress: abdication failover is detection-independent. The operator
verb \code{abdicate} reads the leader's live (era, view), targets the
next-in-era successor view, and drives the standard view change
synchronously --- the detector never waits. Three cycles were driven so
that every genesis node held leadership (n1 cycled first, then n2, then
n3); every cycle answered \code{accepted:true}. The client-visible failover
--- the cycle's begin anchor to the first client operation served on the
abdicated node's connection --- is 30, 27, and 26~ms per cycle (the verb
drive itself 8, 8, 7~ms; full settle of all three voters at their new view
145--156~ms; $n=1$ per cycle, 3 cycles). The same ladder then stopped the
leader cleanly and let the detector do the work: the timeout-driven
takeover is 20,370~ms under the 3{,}000--5{,}000~ms randomized detector
(new leader n2 at view 86's successor era; the stopped node rejoined
42,991~ms after its boot). The contrast on identical knobs, identical load,
and the same measurement rule (first client operation served) is
679--784$\times$ (20,370~ms against 26--30~ms).

The crash/partition run repeats the contrast under load and it holds:
abdication under load failover is 30, 27, and 22~ms per cycle (drives 11,
6, 9~ms; leadership rotated n1 $\to$ n2 $\to$ n3) with ZERO client-visible
errors in all three windows --- both the polite fleet and the aggressive
hammer (364 hammer gets, zero errors, p50 19.2~ms / p99 29.9~ms / max
30.5~ms over the 29.6~s window). The detector-bound contrast on the
partitioned view is 20,318~ms, so the cross-run factor spans 677--923$\times$
(both runs' abdication cycles against both detector-bound takeovers). The
detection-independent class also covers a whole-cluster restart: the
leader's own view line stands 9~ms after its process start (restored from
the superblock) and the first client operation is served 122~ms after the
restart anchor (steady-state run, $n=1$ per scenario row) --- a timing no
knob change moves, because no detector is involved.

\subsection{The crashed-member rejoin fence}\label{sec:exp-limitation}

One path does not come back on this tree, and the paper states it as fact
rather than narrating around it. A SIGKILL-crashed member whose process is
restarted reads its durable state dirty, bumps its identity, announces the
reincarnation to the peers --- and every peer refuses the announcement,
because it carries the pre-kill view: \code{ReincarnationRefused} with the
sender's old (era, view). The announced node then sits fenced
(\code{restarting}/\code{view\_change}, \code{voting=0}) for the full 150~s
measurement budget, no remap notice ever fires at any peer (0 of 9 family
kills; remap counts 0/0/0 for the whole run), and 1,155 refusals are
counted across the run (n1 387, n2 333, n3 435). The fence is
depth-independent and deterministic: all 9 crash-rejoins across three
attempts fence identically --- at view 0, view 1, view 122, and view
1,395 --- and the newest named diagnostic at the fenced node varies
(\code{ReincarnationRefused}, \code{EvidenceNotCollected},
\code{ViewMismatch}) while the outcome does not. While a node sits fenced

parked boot-fence/era-fold defect family: the evidence --- the refused
announcement with the pre-kill view, the never-firing remap walk, the
depth-independent fence at four view depths, and the 9/9 repetition --- is
captured in the run directories, the finding is core-side by the bug
provenance of this demonstration (every resurrection requirement was met:
the loop shut down, the state flushed, and the announcement was still
refused), and the upstream engagement is pending; every scenario that did
not need the crashed node completed on the two-of-three cluster.
